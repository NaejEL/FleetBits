# ─────────────────────────────────────────────────────────────────────────────
# Every version below is pinned exactly. The four marked (1) and (2) moved
# together, as one set, because they cannot move apart:
#
# (1) `fastapi>=0.116.0` floated onto FastAPI 0.141, which registers the routes
#     of include_router() as _IncludedRouter objects. prometheus-fastapi-
#     instrumentator 7.0.0 cannot name those and raises AttributeError on every
#     request through its middleware — 60 of 89 tests failed on a fresh install.
#     Instrumentator 8.x fixes it and requires starlette 1.x.
# (2) starlette 0.49.1, python-multipart 0.0.22 and pytest 8.3.5 carried 22
#     known CVEs between them (pip-audit, the pre-commit hook of this repo):
#     Host-header URL reconstruction, several parser denial-of-service issues,
#     and the pytest /tmp permission issue. The fixed versions are starlette
#     1.3.1+, python-multipart 0.0.31 and pytest 9.0.3 — so the starlette bump
#     that (1) needs is also the one the CVEs need.
#
# (3) The Dockerfile base image moved from python:3.12-slim to python:3.15-slim.
#     Four more pins had to move with it, and for two distinct reasons:
#       - asyncpg 0.30.0, psycopg2-binary 2.9.10 and pydantic 2.10.3 (which
#         pins pydantic-core 2.27.1) publish no cp315 wheel. pip fell back to
#         building them from source inside the slim image, which has no
#         toolchain, and `pip install` died with
#         "Failed to build asyncpg psycopg2-binary pydantic-core". The first
#         releases that ship cp315 manylinux wheels are asyncpg 0.32.0,
#         psycopg2-binary 2.9.13 and pydantic-core 2.48.0 — reached here
#         through pydantic 2.14.3, which pins pydantic-core 2.50.4.
#       - SQLAlchemy 2.0.36 installs on 3.15 but cannot import the models:
#         Python 3.15 made typing.Union.__getitem__ reject a plain tuple, and
#         SQLAlchemy's make_union_type() called it that way, so every
#         declarative class raised TypeError at import. SQLAlchemy first
#         advertises 3.15 in its trove classifiers at 2.0.52, and 2.0.52 does
#         already import the models cleanly — so the floor is 2.0.52, not
#         2.0.57. 2.0.57 is simply the current head of the 2.0 line and the
#         release actually verified here. It stays on the 2.0 line; its wheel
#         is pure Python, the optional C extensions are not built for 3.15 yet.
#     The set in (1)/(2) did NOT have to move for the interpreter bump.
#
# pip-audit on this file: no known vulnerabilities.
# Verified with `python -m pytest` on BOTH interpreters in play — Python 3.15,
# which the Dockerfile and the compose stack use, and Python 3.12, which the
# workflows still set up for the pytest and pip-audit jobs: 158 passed,
# 9 skipped on each.
